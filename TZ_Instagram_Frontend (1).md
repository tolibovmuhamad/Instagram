# Техническое задание
## Разработка веб-клиента (frontend) для клона Instagram

**Версия:** 1.0
**Дата:** 12.07.2026
**Backend API:** https://instagram-api.softclub.tj/swagger/index.html

---

## 1. Общая информация о проекте

### 1.1 Описание
Разработка веб-приложения — клона Instagram, повторяющего оригинальный дизайн и ключевые пользовательские сценарии (лента, сторис, профиль, лайки/комментарии, подписки, личные сообщения).

Backend-часть уже реализована (ASP.NET Core Web API, PostgreSQL, JWT), команде необходимо разработать **клиентскую часть (frontend)**, интегрированную с существующим API по Swagger-спецификации.

### 1.2 Цель проекта
Создать функциональный, адаптивный веб-клиент, визуально и по UX максимально близкий к оригинальному Instagram, полностью покрывающий доступные возможности backend API.

### 1.3 Формат
Учебный/командный проект (pet-project), результат — рабочее веб-приложение с возможностью деплоя (Vercel/Netlify).

## 2. Технологический стек

### 2.1 Backend (уже реализован, не разрабатывается заново)
| Компонент | Технология |
|---|---|
| Язык/платформа | C# / ASP.NET Core Web API |
| Архитектура | Clean Architecture (Domain / Infrastructure / WebApi) |
| БД | PostgreSQL + Entity Framework Core |
| Авторизация | JWT Bearer |
| Маппинг | AutoMapper |
| Документация API | Swagger / OpenAPI |
| Realtime | **Отсутствует** — SignalR/WebSocket на бэкенде не реализован. Чат и уведомления работают через обычные REST-запросы |

### 2.2 Frontend (предмет разработки)

**Основа:**
- Next.js (App Router) + TypeScript
- Axios — HTTP-клиент
- TanStack Query (React Query) — кэширование, инвалидация, работа с серверным состоянием поверх axios
- Zustand — клиентский стейт (авторизация, UI-состояние: модалки, темы и т.п.)
- JWT — хранение и передача токена авторизации
- Tailwind CSS + shadcn/ui — стилизация и UI-кит

**Дополнительно (рекомендуется добавить):**
| Библиотека | Назначение |
|---|---|
| React Hook Form + Zod | формы (регистрация, логин, создание поста, редактирование профиля) с валидацией |
| openapi-typescript / orval | генерация TS-типов и клиента прямо из Swagger-спеки бэкенда |
| lucide-react | иконки (совместимо с shadcn) |
| sonner | тосты/уведомления об ошибках и успехах |
| framer-motion | анимации (лайк, появление постов, переходы) |
| date-fns / dayjs | относительное форматирование дат ("5 минут назад") |
| react-easy-crop | кроп изображений перед загрузкой (аватар, посты) |
| browser-image-compression | сжатие изображений перед отправкой на сервер |
| react-intersection-observer | infinite scroll для ленты, reels, комментариев |
| next/image | оптимизация изображений |

**Dev-инструменты:** ESLint, Prettier, Vitest/Jest + Testing Library, Playwright (e2e).

### 2.3 Важные технические нюансы для команды
- Backend CORS уже разрешает `http://localhost:3000` — фронтенд можно поднимать локально без доп. настройки.
- Realtime-обновлений (лайки/сообщения в реальном времени) на бэкенде нет — если нужны, закладывать через периодический рефетч (polling через React Query, `refetchInterval`), а не через WebSocket/SignalR.
- Все ответы API оборачиваются в стандартный конверт:
```json
{
  "data": { },
  "errors": [],
  "statusCode": 200
}
```
Пагинированные списки дополнительно содержат `pageNumber`, `pageSize`, `totalPage`, `totalRecord`.

## 4. Функциональные требования и соответствующие API-эндпоинты

### 4.1 Авторизация и аккаунт (`/Account`)
- Регистрация: `POST /Account/register` (userName, fullName, email, password, confirmPassword)
- Вход: `POST /Account/login` (userName, password) → JWT-токен
- Забыли пароль: `DELETE /Account/ForgotPassword`
- Сброс пароля: `DELETE /Account/ResetPassword`
- Смена пароля: `PUT /Account/ChangePassword`

**Экраны:** страница входа, страница регистрации, восстановление пароля, смена пароля в настройках.

### 4.2 Профиль пользователя (`/UserProfile`, `/User`)
- Мой профиль: `GET /UserProfile/get-my-profile`
- Профиль по id: `GET /UserProfile/get-user-profile-by-id`
- Проверка подписки: `GET /UserProfile/get-is-follow-user-profile-by-id`
- Обновление профиля: `PUT /UserProfile/update-user-profile`
- Загрузка/удаление аватара: `PUT /UserProfile/update-user-image-profile`, `DELETE /UserProfile/delete-user-image-profile`
- Сохранённые посты: `GET /UserProfile/get-post-favorites`
- Список/поиск пользователей: `GET /User/get-users`
- История поиска: `add/get/delete-search-history(ies)`, `add/get/delete-user-search-history(ies)`

**Экраны:** страница профиля (свой/чужой), редактирование профиля, поиск пользователей с историей поиска, сохранённые посты.

### 4.3 Посты (`/Post`)
- Лента: `GET /Post/get-posts` (с фильтром)
- Лента подписок: `GET /Post/get-following-post`
- Reels: `GET /Post/get-reels`
- Пост по id: `GET /Post/get-post-by-id`
- Мои посты: `GET /Post/get-my-posts`
- Создание поста: `POST /Post/add-post` (multipart/form-data: изображения, текст, категории)
- Удаление поста: `DELETE /Post/delete-post`
- Лайк: `POST /Post/like-post`
- Просмотр: `POST /Post/view-post`
- Комментарии: `POST /Post/add-comment`, `DELETE /Post/delete-comment`
- Добавить в избранное: `POST /Post/add-post-favorite`

**Экраны:** главная лента, страница поста с комментариями, создание поста (с кропом/превью изображений), лента Reels, сетка постов в профиле.

### 4.4 Сторис (`/Story`)
- Лента сторис: `GET /Story/get-stories`
- Сторис пользователя: `GET /Story/get-user-stories/{userId}`
- Мои сторис: `GET /Story/get-my-stories`
- Просмотр конкретной: `GET /Story/GetStoryById`
- Создание: `POST /Story/AddStories`
- Удаление: `DELETE /Story/DeleteStory`
- Лайк сторис: `POST /Story/LikeStory`
- Отметка просмотра: `POST /Story/add-story-view`

**Экраны:** лента аватарок-сторис сверху ленты, полноэкранный вьюер сторис (с таймером/прогресс-баром как в оригинале), экран создания сторис.

### 4.5 Подписки (`/FollowingRelationShip`)
- Подписчики: `GET get-subscribers`
- Подписки: `GET get-subscriptions`
- Подписаться/отписаться: `POST add-following-relation-ship`, `DELETE delete-following-relation-ship`

> На момент написания ТЗ методы в контроллере закомментированы на бэкенде — уточнить у backend-команды сроки включения перед началом интеграции этого модуля.

**Экраны:** списки подписчиков/подписок (модалка или отдельная страница), кнопка "Подписаться/Отписаться" в профиле и под постом.

### 4.6 Личные сообщения (`/Chat`)
- Список чатов: `GET /Chat/get-chats`
- Чат по id: `GET /Chat/get-chat-by-id`
- Создать чат: `POST /Chat/create-chat`
- Отправить сообщение: `PUT /Chat/send-message` (текст + файл)
- Удалить сообщение/чат: `DELETE /Chat/delete-message`, `DELETE /Chat/delete-chat`

**Экраны:** список диалогов, окно переписки (обновление — через polling, см. п. 2.3).

### 4.7 Геолокация (`/Location`)
- CRUD локаций: `get-Locations`, `get-Location-by-id`, `add-Location`, `update-Location`, `delete-Location`

**Использование:** выбор города/локации в профиле, возможно — привязка локации к посту (уточнить у backend-команды, если нужно расширение).

## 5. Дизайн и UI/UX

### 5.0 Источник дизайн-референса

Дизайн-референс проекта — **оригинальное веб-приложение Instagram** (Meta Platforms, Inc.). Оно используется исключительно как источник вдохновения и UX-эталон в рамках учебного/некоммерческого проекта: воспроизводится общая структура интерфейса и пользовательские паттерны (раскладка ленты, сторис, профиля и т.д.), без использования официального логотипа, брендинга и иных фирменных элементов Instagram/Meta. Это зафиксировано здесь, чтобы не уточнять источник дизайна повторно в переписке или на защите проекта.

Дизайн ориентируется на оригинальный Instagram (веб-версия):

- **Общая раскладка:** левый сайдбар с навигацией (Главная, Поиск, Reels, Сообщения, Уведомления, Создать, Профиль) на десктопе; нижний таб-бар на мобильных экранах.
- **Лента (Home):** центральная колонка постов + панель сторис сверху + правый блок "рекомендации/подписки" на широких экранах.
- **Пост:** шапка (аватар, ник, локация, меню "..."), медиа (карусель изображений), панель действий (лайк, комментарий, поделиться, сохранить), подпись, превью комментариев, дата.
- **Сторис:** полноэкранный просмотр, прогресс-бар сегментов, свайп/клик влево-вправо, реакция и просмотры (для автора).
- **Профиль:** аватар, статистика (посты/подписчики/подписки), кнопки "Редактировать профиль" / "Подписаться", вкладки (посты — сеткой, сохранённое, отмеченные), bio.
- **Создание поста:** загрузка/кроп изображений (1:1, 4:5, 16:9 как в оригинале), подпись, выбор категории/локации.
- **Модалки:** подписчики/подписки, лайкнувшие пост, комментарии (на десктопе — модалка, на мобильном — отдельный экран).
- **Тёмная/светлая тема** — рекомендуется поддержать (Tailwind + shadcn это упрощают).

Адаптивность обязательна: desktop / tablet / mobile — как у оригинала (3 разных лейаута навигации).

## 6. Нефункциональные требования

- **Адаптивность:** корректное отображение от 360px до 1920px+.
- **Производительность:** ленивая загрузка изображений (`next/image`), виртуализация длинных списков при необходимости, infinite scroll вместо пагинации кнопками.
- **Безопасность:** JWT не хранить в localStorage в открытом виде без осознанного решения команды (обсудить httpOnly cookie vs хранение в памяти + refresh); экранирование пользовательского контента (защита от XSS в комментариях/подписях).
- **Обработка ошибок:** единый обработчик ошибок API (interceptor axios + `errors[]` из ответа), понятные сообщения пользователю через toast.
- **Доступность (a11y):** базовая поддержка — alt для изображений, фокус-стили, навигация с клавиатуры в модалках.

## 9. Критерии приёмки (Definition of Done)

- Все перечисленные экраны реализованы и адаптивны (desktop/mobile).
- Все перечисленные в разделе 4 эндпоинты подключены и обрабатывают состояния loading/error/empty.

- Код разбит по фичам, переиспользуемые UI-компоненты вынесены в `components/ui`.
