# Roadmap — Instagram Frontend

Дорожная карта разработки фронтенд-клиента Instagram поверх готового бэкенда
(ASP.NET Core Web API). Разрабатывается **только фронтенд**. Источник истины —
ТЗ (`TZ_Instagram_Frontend (1).md`), выжимка — `CLAUDE.md`.

**Стек:** Next.js (App Router) + TypeScript · Axios · TanStack Query · Zustand ·
Tailwind CSS + shadcn/ui · React Hook Form + Zod · JWT.
Типы API — генерировать из Swagger (`openapi-typescript` / `orval`).

> у `get-following-post`: я + подписки, поэтому лента сторис почти пуста до

### Багфикс — 404 при создании чата (2026-07-15)

- [x] `/Chat/create-chat` возвращает чат целиком (`{id, userId, userName, …}`), а не его id —
      в Swagger тело ответа не описано, проверено запросом к API. `NewChatDialog` подставлял

      Исправлено на `chat.id`; проверено сквозняком: выбор собеседника открывает `/messages/4`.

### Важно — refreshToken одноразовый, повторное использование завершает ВСЕ сессии

Бэкенд ротирует refreshToken и считает повторное использование атакой: второй запрос со
старым токеном отвечает `401` «Обнаружено повторное использование токена. Все сессии
завершены.» — и это не пустая угроза, сессии действительно завершаются (проверено).

Приложение опрашивает сервер поллингом из нескольких хуков, поэтому по истечении access
токена 401 прилетает пачкой — наивная реализация запустила бы несколько обновлений разом
и разлогинила пользователя на всех устройствах. Защита в `lib/api/client.ts`:

1. `refreshPromise` — одно обновление на вкладку, остальные ждут его результат;
2. Web Locks (`navigator.locks`) — сериализация между вкладками; получив лок, проверяем,
   не обновил ли токен кто-то другой, пока мы ждали;
3. `store/auth` перечитывает localStorage по `storage`-событию, чтобы вкладки видели
   общую пару токенов.

Тест `lib/api/__tests__/refresh.test.ts` фиксирует инвариант «пачка 401 → ровно одно
обновление» (проверено мутацией: без single-flight падает).

## Открытые вопросы (уточнить с backend-командой)

1. **Одобренный гость эфира не получает право вещать:** после `approve-guest` его `join`
   по-прежнему отдаёт LiveKit-токен с `canPublish: false`. Нужно повышать права гостю —
   иначе вся ветка «гости в эфире» бесполезна. Фронт готов.
2. **Записи эфиров:** `recordingUrl` всегда `null`, из-за чего `/Live/save-to-story` отвечает
   400. Планируется ли включать egress-запись в LiveKit?

4. Планируется ли realtime (SignalR) для чата/уведомлений, или polling — постоянное решение?
   (Контроллер `Presence` намекает на polling.)
5. Пароли и токены передаются в query-строке (`ChangePassword`, `ResetPassword`,
